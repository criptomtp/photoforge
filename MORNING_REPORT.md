## 2. ⚠️ Як це застосувати (ПОСЛІДОВНІСТЬ ВАЖЛИВА)

Міграція-`030` (revoke) **ламає поточний прод-код**, бо він ще кличе `try_consume`/`increment` через authenticated-клієнт. Тому:

**Zero-downtime (рекомендовано):**
1. Застосуй у Supabase SQL Editor (або `supabase db push`) міграції **025 → 029** (вони сумісні зі старим кодом, лише додають стовпці/функції).
2. Зроби merge гілки `overnight/security-money-fixes` → `main` і дочекайся зеленого деплою Vercel (новий код уже ходить через service-role).
3. **Тільки тепер** застосуй міграцію **`030_revoke_money_rpcs.sql`** (закриває C1).

**Простіше (якщо не страшно ~1 хв вікна):** застосуй усі 6 міграцій одразу + одразу merge. Між revoke і деплоєм буде ~хвилина, поки free-квота-генерація недоступна. Для соло-проєкту з кількома юзерами — прийнятно.

> Перевір C1 ПІСЛЯ застосування: у SQL Editor
> `SELECT proname, proacl FROM pg_proc WHERE proname IN ('credit_tokens_tx','deduct_tokens_tx','try_consume_free_generation');`
> У `proacl` НЕ має бути `authenticated`. Якщо є — revoke не спрацював.

> ⚠️ Я **не зміг перевірити** реальний стан живої БД (немає доступу). Усі міграції написані ідемпотентно (`if not exists`, `create or replace`), але перед `db push` бажано глянути `supabase migration list`, що 023 і раніші реально застосовані й немає розбіжностей.

## 4. Свідомо відкладено (з готовим рецептом — потрібне твоє рішення)

### M1. Guard-тригер на службові колонки `generations` (MEDIUM)
Зараз юзер може PATCH-нути ВЛАСНІ generation-рядки (status/image_urls) напряму через PostgREST. Імпакт — псування своїх же даних (не гроші, не крос-юзер), тому відклав: безпечне впровадження вимагає перевести записи `generations` у `/api/generate` і `/api/batch/item` з authenticated- на service-role-клієнт (інакше тригер заблокує їхні ж легітимні апдейти), а це рефакторинг двох найгарячіших роутів — зависокий ризик для беззупинного нічного прогону. **Рецепт:** (1) у цих двох роутах заміни `supabase.from("generations").update(...)` на `supabaseAdmin...`; (2) додай тригер-аналог `guard_profile_update` для `generations`, що блокує зміну службових колонок для ролі authenticated. Готовий зробити під твоїм наглядом.

### O1. Експорт/монетизація AI-лістингів (найдешевший апсейл)
Лістинги вже генеруються й лежать у `generations.listing`, але нікуди не виводяться. Це продуктове рішення (де саме показати: кнопка «копіювати» в QA / колонка в bulk-export / push на Etsy) — лишив тобі, бо потрібен твій вибір формату/місця. Технічно — кілька годин.

### B4 — закрито побічно
